Real-user continuity value and coaching effectiveness are still unproven. Entries below retain their original dated development status as history.

## Unreleased development — 2026-10-05

Implemented the first manual case-continuity MVP: a conditionally loaded return workflow, a compact Markdown template and an optional standard-library file helper. The host reads the user-identified case, compares the earlier plan with the actual return account, and explains whether the next move changes. Save consent remains distinct from plan adoption; snapshot-only and scoped ongoing permissions are separate. The helper checks actual authorization inputs, exclusive creation, scoped updates and stale-file reads, and reports write status accurately. It does not interpret evidence, infer consent, create automatic memory or select advice.

Added offline temporary-file tests for plan/attempt separation, attributed and conflicting reports, corrections, unchanged moves, no-attempt returns, consent scope, preservation of user edits and failed writes. These verify record representation and persistence; semantic interpretation, product value and coaching effectiveness remain unproven. PM implementation/persistence review precedes any live trial. Public export inventories include the new workflow, template, helper and full-project tests; no public release or package version bump is performed. Source cards, runtime, G/H, policy, strictly > 0.25 cutoff, presentation and historical study snapshots remain unchanged.

## Unreleased development — 2026-10-03

Added a portable [first-use onboarding guide](skills/compound-intelligence/references/onboarding.md), linked from the single skill entry point and existing guides. Users choose local coaching or Jev, enter their own key in a hidden terminal prompt with a no-echo warning guard, and check readiness in the actual execution environment. The guide distinguishes key presence, live connectivity and case-data consent. It reuses doctor/smoke; no new runtime command, persistent key file, plugin or MCP service is required. Paid tests remain explicitly approved.

Added an agent-led case-understanding procedure to the existing context contract and main entry point: start from the available conversation, preserve corrections, ask one neutral question when it changes the next move, and stop at useful advice or conditional alternatives. Its working brief feeds existing method selection; preflight clarification returns to the same case. This adds no Jev question calls, state fields, persistent case store or scheduler. An internal conversation-design record distinguishes the implemented first version from future Jev experiments and records the gstack workflow lessons. The default workspace keeps advice beside practice/reflection and opens references without moving the editor. The earlier document template remains available for comparisons. Notes export/import, readable reflow, printing and script-free reading remain local; rendering adds no coaching decisions or model calls.

Rebuilt both HTML templates using the user's new Ramp style reference: monochrome surfaces, an Obsidian next-move panel, regular-weight sans-serif typography and chartreuse action/active states. Replaced the old cream/sage styling throughout controls, fields, references, notices and responsive/print layouts. The content handoff and workspace behaviour remain intact. The redesigned demo passed the same desktop/browser checks and all 122 offline tests; the alternate reading layout was also checked locally.

The user accepted the workspace direction. The internal development checkpoint records 122 passing offline tests and browser checks for the synthetic demo, including no page scrolling at both tested laptop viewports. These are software checks and user feedback, not effectiveness evidence. See the [development guide](docs/DEVELOPMENT.md) and [presentation guide](presentation/README.md).

The book reread also produced a separate internal 228-entry knowledge inventory, with proposed placements; that research is not included in public packages and the preserved cards were not changed. Package version 0.2.2 and the runtime/policy remain unchanged. No new release archives were built for this October 3 development work.
